## 核心设计决策

### 1. 渲染方案：浏览器逐帧渲染 + ffmpeg

**选了什么**：Python 驱动无头浏览器（CDP），逐帧截图，ffmpeg 编码。

**为什么**：
- 预览与成片共用**同一份 Canvas 代码**，真正所见即所得
- 视觉零偏差（由 `tools/test_parity.mjs` 逐像素比对守住）

**否决的方案**：

| 方案 | 否决原因 |
|---|---|
| Python + Pillow 逐帧绘制 | 必须重写全部渲染代码，双份实现易偏差 |
| 实时渲染 + 录屏 | 掉帧与同步不可靠，不适合专业输出 |

**实测结果**：4 路并行最优。

### 2. 组件化：自包含渲染单元

每个组件调 `register()` 声明自己，接收 `(g, w, h, 样式)`，
自己负责画满自己的矩形。

**为什么**：这样 GUI 的拖拽编辑才可能实现。

### 3. 主题系统：色板 + 质感 + 绽放

一套主题定义四部分：

| 部分 | 位置 | 作用 |
|---|---|---|
| 色板与字体 | `preview/themes/artdirections.json` | 颜色、字体、字号 |
| 质感 | `src/core/surfaces.js` 的 `SURFACE.<名>` | 填充/描边/标记/网格的画法 |
| 绽放 | `src/bloom/themes/<名>.js` 的 `BLOOM.<名>` | 音符落点的动画 |
| 数据色 | `artdirections.json` 的 `data`/`data2`/`data3` | 各组件的**数据主体**用色 |

**数据色是后期加的**：早期只有 `accent`（强调色），
导致所有组件的数据主体都是灰阶、看不出设计差异。
拆出 `data` 系列后，各主题才有了真正的视觉区分。

### 4. 窗口宿主：pywebview

**选了什么**：pywebview（WebView2）做无边框窗口 + 自绘标题栏。

**为什么**：
- Edge `--app` 模式自带一条 Edge 画的标题栏，Win32 层去不掉
- pywebview 是**真无边框**，标题栏完全可控

**回退**：无 pywebview 时退回 Edge `--app` 模式。

### 5. 打包：PyInstaller onedir

**为什么是 onedir 不是 onefile**：
- 启动快（不用每次解压 100+ MB）
- 目录结构可见，出问题好排查
- 打成 zip 分发，用户解压即用

详见 [`PACKAGING.md`](PACKAGING.md)。

## 数据流

```
FLP 工程 ──→ Parser ──→ project_snapshot.json ──┐
                     （稳定 Schema，只保留 PPQ）  ├─→ 渲染 ─→ mp4
音频文件 ──→ 音频分析（波形/频谱/onset/鼓组）────┘
```

**关键约束**：

- 渲染层**只读** `project_snapshot.json`，不直接依赖 PyFLP 对象
- 时间统一保留 PPQ tick，仅在需要秒时用 `ppq` + `tempo` 显式换算
- 音频为唯一时间基准，视觉按帧号推算，避免双计时器漂移
